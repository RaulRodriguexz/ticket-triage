14 labelled test cases, each run 3× for stability. The set is built to catch failures, not flatter the model: a caps-lock “URGENT” that is really low priority, an out-of-scope request, and a prompt-injection attempt. A critical ticket is never downgraded, and the suggested reply is blocked if it promises a deadline or a refund. Real numbers are filled in once measured against the live API.
